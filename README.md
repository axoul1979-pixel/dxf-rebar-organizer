# DXF Rebar Auto-Tidy — Αυτόματη τακτοποίηση κειμένων οπλισμού σε ξυλοτύπους

Pipeline σε καθαρή Python (χωρίς εξαρτήσεις — μόνο standard library) που διαβάζει
DXF ξυλοτύπου (AutoCAD R12/ASCII, blocks FLn_*), τακτοποιεί αυτόματα ΟΛΑ τα
κείμενα οπλισμών (δοκών, πλακών, κολωνών, δεικτών πλακών) ώστε να μην υπάρχει
καμία επικάλυψη ή κομμένο κείμενο, και γράφει νέο DXF χωρίς να αλλοιώσει καμία
οντότητα του σχεδίου (ίδιος αριθμός οντοτήτων, μόνο μετατοπίσεις insert/MTEXT).

## Γρήγορη χρήση

```bash
# 1) Τακτοποίηση (ντετερμινιστικά - θωρακισμένο από bytecode cache εσωτερικά)
PYTHONHASHSEED=0 python run_any.py ΕΙΣΟΔΟΣ.dxf ΕΞΟΔΟΣ.dxf offsets.pkl

# 2) ΑΝΕΞΑΡΤΗΤΟΣ έλεγχος πάνω στο παραγόμενο αρχείο (πρέπει AUDIT_TOTAL 0)
python audit_output.py ΕΞΟΔΟΣ.dxf ΕΙΣΟΔΟΣ.dxf

# 3) Επαλήθευση απαράβατων κανόνων (πλευρές/πλάκες/κατά-μήκος)
python verify_all.py ΕΙΣΟΔΟΣ.dxf offsets.pkl
```

Κανένα αρχείο δεν θεωρείται παραδοτέο αν το audit δεν τυπώσει `AUDIT_TOTAL 0`.
Δύο τρεξίματα με ίδια είσοδο παράγουν byte-προς-byte ταυτόσημη έξοδο (md5).

## Απαράβατοι κανόνες (όλοι με αυτόματη επιβολή ΚΑΙ αυτόματο έλεγχο)

1. **Κείμενα ράβδων μόνο ΚΑΤΑ ΜΗΚΟΣ.** Κείμενο BEAMBAR/SLABBAR κινείται
   αποκλειστικά παράλληλα στη ράβδο του (κατά τον άξονά της), ποτέ κάθετα.
2. **Πλευρά Άνω/Κάτω κλειδωμένη.** Κάθε beambar μένει στην πλευρά της δοκού του
   που όρισε ο μελετητής (έλεγχος ως προς τον άξονα της δοκού) — και ως προς
   κάθε γειτονικό κείμενο δοκού. Μετακίνηση σιδήρου δοκού μόνο μέσα στη
   **ζώνη** του: |απόσταση από άξονα| ≤ βασική + 0.35μ, ίδια πλευρά.
3. **Ράβδοι πλακών ποτέ εκτός πλάκας.** Ανά άξονα με «υγιές» περίγραμμα:
   εντός [πλάκα ∪ φυσική έκταση]. Σε εκφυλισμένο/άγνωστο άξονα ΚΑΙ καθολικά:
   **±0.35μ από τη ΦΥΣΙΚΗ θέση** σε κάθε άξονα — η φυσική θέση (το σχέδιο του
   μηχανικού) είναι η μόνη πάντα-σωστή αναφορά. Μικρή τακτοποίηση ναι,
   μετακόμιση ποτέ.
4. **Ενιαία πύλη κίνησης σιδήρου.** Κάθε μετατόπιση ράβδου, από οποιοδήποτε
   πέρασμα, περνά από το `_bar_move_ok` (πλευρά+ζώνη για δοκούς, πλάκα+±0.35
   για πλάκες). Καμία εξαίρεση.
5. **Καμία παράλληλη τομή.** Γραμμή με γωνία < ~20° (cos > 0.94) από τη φορά
   ανάγνωσης δεν κόβει ΠΟΤΕ κείμενο (έλεγχος στο ΠΛΗΡΕΣ κουτί - ο «πυρήνας»
   είναι τυφλός στα μονογραμμικά). Οι λεπτές ΚΑΘΕΤΕΣ διελεύσεις είναι η
   αποδεκτή σύμβαση ξυλοτύπου. Ισχύει και αντίστροφα: γραμμή ράβδου δεν
   παραλληλο-κόβει ξένο κείμενο (επιτρέπονται μόνο κινήσεις που δεν προσθέτουν
   ΝΕΑ θύματα, με απαίτηση προόδου).
6. **Μηδέν επικαλύψεις, ελάχιστο κενό κειμένων 0.04μ, κανένα κείμενο πάνω σε
   κυκλάκι δείκτη Πx** (ισχύει για ΟΛΕΣ τις κατηγορίες, και για ετικέτες
   κολωνών).
7. **Δύο επίπεδα ελέγχου θέσης.** `is_ok_full`: αυστηρό (απόσταση από ξένα
   hatch 0.25μ, μηδενική ανοχή σε διασχίσεις). `is_ok_relaxed`: hatch 0.05μ,
   απορρίπτει παράλληλες τομές, ανέχεται ≤1 **γεωμετρική** γραμμή (οι κοινές
   ακμές πλακών είναι σχεδιασμένες 2× — μετράνε ως μία, `count_line_crossings_geom`).
8. **Τοιχία (λόγος πλευρών > 2).** Ετικέτα δίπλα στην παρειά — ΜΕΣΑ στο κτίριο
   ή έξω, όπου υπάρχει νόμιμος χώρος — αλλά **ποτέ πάνω στο σώμα/hatch του
   ίδιου του τοιχίου**. Αν καταλήξει μακριά (επικάλυψη σώματος ή απόσταση
   παρειάς > 0.45μ), γίνεται επανατοποθέτηση με άνοιγμα χώρου: εύρεση κοντινής
   θέσης με πολλαπλά σημεία εκκίνησης (κέντρο + 4 παρειές), αγνοώντας τα
   μετακινήσιμα κείμενα ράβδων, και μετά εκδίωξή τους με την αλυσίδα. Αποδοχή
   μόνο σε σαφή βελτίωση (>0.15μ) και ποτέ πάνω σε κυκλάκι/σώμα τοιχίου.

## Αρχιτεκτονική

- `pipeline_v11.py` — η καρδιά: ανάλυση blocks, αρχική τοποθέτηση ανά
  κατηγορία, cross-category repair, και το τελικό τμήμα: `_final_passes()`
  (pull ετικετών κολωνών+επανατοποθέτηση τοιχίων → εκκαθάριση κύκλων με
  εξαντλητικό πλέγμα 0.05 και συνδυασμό σίδερο+δείκτης → εκκαθάριση παράλληλων
  τομών → επιδιόρθωση επικαλύψεων με slide→αλυσίδα→μετακίνηση σιδήρου) μέσα σε
  **βρόχο συμφιλίωσης** έως 4 γύρων με εσωτερικό audit (`_internal_bad_count`)
  μέχρι το μηδέν.
- `engine.py`, `analyze.py`, `parse_dxf.py` — ανάγνωση DXF/blocks/inserts.
- `beambar_engine.py` — γεωμετρία κειμένων: πλάτη χαρακτήρων (0.38 κεφαλαία/
  0.45 πεζά+σύμβολα/0.94 πλατιά/0.83 Φ κ.λπ.), συνολικό πλάτος +0.25×ύψος,
  bbox με περιστροφή, τομές τμήμα-κουτί.
- `compute_beambar3.py`, `compute_slabbar3.py`, `compute_beamtext_slabmarker.py`,
  `compute_column_text.py` — αντιστοίχιση ράβδων σε δοκούς/πλάκες, βασικές
  θέσεις, δείκτες πλακών, ετικέτες κολωνών.
- `hatch_engine.py` — πολύγωνα hatch και έλεγχοι επικάλυψης.
- `perimeter.py` — αποτύπωμα κτιρίου (footprint), εσωτερικό/εξωτερικό,
  εξωτερικές κατευθύνσεις.
- `patcher.py`, `patch_slab_marker.py`, `patch_style.py` — εγγραφή του τελικού
  DXF: μετατοπίσεις insert, MTEXT εντός block ανά layer, μετακίνηση δείκτη
  (κύκλος+κείμενα+γραμμές-οδηγοί μαζί). ΚΑΜΙΑ προσθήκη/διαγραφή οντότητας.
- `global_repair.py` — γενικά εργαλεία επισκευής (ιστορικό στάδιο, μέρη του
  έχουν μεταφερθεί στο pipeline).
- `run_any.py` (γενικό), `run.py` (συντόμευση για το πρώτο έργο) — και τα δύο
  με `sys.dont_write_bytecode = True` (τα μπαγιάτικα __pycache__ ήταν πηγή
  «διορθώσεων-φαντασμάτων»· μην το αφαιρέσεις).
- `audit_output.py` — ΑΝΕΞΑΡΤΗΤΟΣ ελεγκτής πάνω στο ΤΕΛΙΚΟ DXF (ξαναδιαβάζει
  το αρχείο από το μηδέν): Α επικαλύψεις, Β οριακά κενά <0.03, Γ κείμενα σε
  κυκλάκια, Δ παράλληλες τομές (για ετικέτες δοκών εξαιρείται η δική τους δοκός
  και οι δικοί της ράβδοι — η ετικέτα ζει μέσα στη δοκό εξ ορισμού),
  Ε ράβδοι πλακών εκτός ±0.35 από τη φυσική θέση, ΣΤ δείκτες πλακών εκτός
  ορίων (εντός πλάκας σε υγιείς άξονες, ±0.35 από φυσική σε εκφυλισμένους ή
  χωρίς αναγνωρισμένο περίγραμμα). Τυπώνει `AUDIT_TOTAL`.
- `verify_all.py` — επαλήθευση κανόνων πάνω στα offsets: 1 πλευρές Άνω/Κάτω,
  2 ράβδοι εντός πλάκας/±0.35, 3 κατά-μήκος-μόνο, 4-6 επικαλύψεις/κενά/κύκλοι.
- `verify*.py`, `diag.py`, `dbg*.py`, `test_*.py`, `cmp.py` — διαγνωστικά και
  δοκιμές ανάπτυξης (προαιρετικά, δεν χρειάζονται για παραγωγή).

## Κατώφλια (σταθερές — μην αλλάξουν χωρίς λόγο)

| Σταθερά | Τιμή | Πού |
|---|---|---|
| MIN_TEXT_GAP | 0.04 μ | ελάχιστο κενό κειμένων |
| Ζώνη ράβδων πλάκας | φυσική ±0.35 μ/άξονα | _slabbar_bounds_ok, audit Ε, verify 2 |
| Ζώνη ράβδων δοκού | βασική απόσταση +0.35 μ, ίδια πλευρά | BEAMBAR_SIDE |
| Παράλληλη τομή | cos > 0.94 (~<20°), πλήρες κουτί | parallel_cut_full |
| PARALLEL_CROSS_DEG | 25° (πυρήνας, ιστορικό) | count_line_crossings |
| Hatch full / relaxed | 0.25 / 0.05 μ | is_ok_full / is_ok_relaxed |
| Ανεκτές διασχίσεις (relaxed) | ≤1 γεωμετρική γραμμή | count_line_crossings_geom |
| Πλέγμα δείκτη | βήμα 0.05, εκφυλισμένος άξονας: φυσική κύκλου ±0.35 | πέρασμα κύκλων |
| Τοιχίο: ενεργοποίηση επανατοποθέτησης | επικάλυψη σώματος ή παρειά >0.45 μ | _final_passes |
| Τοιχίο: αποδοχή | βελτίωση >0.15 μ, όχι σε σώμα/κύκλο | _final_passes |
| Χαρακτήρες: κεφαλαία/πεζά/πλατιά/Φ | 0.38/0.45/0.94/0.83 ×ύψος, σύνολο +0.25×ύψος | beambar_engine |

## Ντετερμινισμός & υγιεινή

- Τρέξιμο πάντα με `PYTHONHASHSEED=0` (τα σκριπτ δεν γράφουν bytecode μόνα τους).
- Όλες οι διατρεχόμενες συλλογές repair είναι ταξινομημένες (`sorted`).
- Debug μόνο με μεταβλητές περιβάλλοντος, μηδενική επίδραση χωρίς αυτές:
  `DEBUG_CN=<όνομα block>` (πέρασμα κύκλων + επανατοποθέτηση τοιχίων),
  `DEBUG_PAIR=1`, `DEBUG_S47=1` (ιστορικά διαγνωστικά).

## Γνωστά ανοιχτά (τεκμηριωμένα, όχι κρυμμένα)

- leukos K7 (COLUMN_TEXT12): ετικέτα στα 0.90 μ από την παρειά — η κοντινότερη
  τσέπη δεν καθαρίζει νόμιμα με τους τρέχοντες κανόνες.
- Προαιρετική προτίμηση «ανατολικής στοίβας» για ζεύγη τοιχίων σε γωνία
  (τύπου K82/K83): οι θέσεις είναι καθαρές και κοντά, αλλά η πλευρά επιλέγεται
  από τη διαθεσιμότητα, όχι από αισθητική προτίμηση πλευράς.

## Φάκελος standalone/ (Pyodide / browser / online runners)

- `standalone/pipeline_v11.py` — drop-in αντικατάσταση του pipeline_v11.py με
  ΟΛΑ τα modules ενσωματωμένα: για περιβάλλοντα που φορτώνουν μόνο αυτό το
  όνομα αρχείου (π.χ. web σελίδα με Pyodide). Ίδιο API + `tidy/audit/verify`.
- `standalone/autotidy_all_in_one.py` — ίδιο περιεχόμενο με ουδέτερο όνομα.

Και τα δύο παράγουν byte-προς-byte το ίδιο αποτέλεσμα με το κανονικό πακέτο
(επαληθευμένο με md5).

## Φάκελος standalone/ (Pyodide / browser / online runners)

Δύο αυτόνομα αρχεία, το καθένα με ΟΛΟ το πακέτο ενσωματωμένο - δεν χρειάζονται
τίποτα άλλο από το DXF σου:

- `standalone/pipeline_v11.py` - drop-in αντικατάσταση με το ΙΔΙΟ όνομα, για
  περιβάλλοντα που κάνουν `import pipeline_v11` (ίδιο API + `tidy/audit/verify`).
- `standalone/autotidy_all_in_one.py` - ίδιο περιεχόμενο με ουδέτερο όνομα.

Και τα δύο παράγουν byte-προς-byte το ίδιο αποτέλεσμα με το κανονικό πακέτο
(ελεγμένο με md5).

## Μονοαρχειακή έκδοση (Pyodide / browser / online runners)

Το `autotidy_all_in_one.py` περιέχει ΟΛΟ το πακέτο σε ένα αρχείο (ενσωματωμένα
modules). Δεν χρειάζεται τίποτα άλλο εκτός από το DXF σου:

```bash
python autotidy_all_in_one.py tidy   input.dxf output.dxf offsets.pkl
python autotidy_all_in_one.py audit  output.dxf input.dxf
python autotidy_all_in_one.py verify input.dxf offsets.pkl
```

Σε Pyodide/notebook:
```python
import autotidy_all_in_one as at
at.tidy("input.dxf", "output.dxf", "offsets.pkl")
at.audit("output.dxf", "input.dxf")
```
Παράγει byte-προς-byte το ίδιο αποτέλεσμα με το κανονικό πακέτο (ελεγμένο με md5).

## Μαζική επεξεργασία (πολλά DXF ενός κτιρίου)

```bash
python run_batch.py ΦΑΚΕΛΟΣ_ΜΕ_ΤΑ_DXF
```
Επεξεργάζεται όλα τα .dxf του φακέλου, παράγει τα _tidied + offsets, τρέχει το
audit σε καθένα, και τυπώνει συγκεντρωτικό πίνακα (αρχείο/χρόνος/AUDIT_TOTAL).

## Απαιτήσεις

Python 3.10+. Καμία εξωτερική βιβλιοθήκη. Είσοδος: DXF ASCII (R12) με blocks
ονοματολογίας `FLn_COLUMNk / FLn_COLUMN_TEXTk / FLn_BEAMk / FLn_BEAM_TEXTk /
FLn_BEAMBARk / FLn_SLABk / FLn_SLABBARk / FLn_FREENODEk`.

## Web εφαρμογή (GitHub Pages)

Το repo περιέχει `index.html`: ενεργοποίησε GitHub Pages (Settings -> Pages ->
Deploy from a branch -> main, / root) και η διεύθυνση του Pages γίνεται
εφαρμογή που τρέχει το pipeline ΜΕΣΑ στον browser (Pyodide): επιλογή DXF ->
Εκτέλεση -> ζωντανό log -> αυτόματο audit (πράσινο μόνο με AUDIT_TOTAL 0) ->
κατέβασμα τακτοποιημένου DXF. Όλα τρέχουν τοπικά στη συσκευή σου - το σχέδιο
δεν ανεβαίνει πουθενά. Στα μεγάλα σχέδια ο browser αργεί πολλαπλάσια από
κανονική Python.
