# DXF REBAR AUTO-TIDY

Εργαλείο για ξυλοτύπους και λεπτομέρειες υποστυλωμάτων που εξάγονται από **FESPA**.
Τρέχει **εξ ολοκλήρου στον browser** — κανένα αρχείο δεν φεύγει από τον υπολογιστή σου.

Δύο πράγματα κάνει:

1. **Τακτοποιεί τα κείμενα οπλισμού** σε κάθε ξυλότυπο (Python, μέσα σε Pyodide).
2. **Συνθέτει το τεύχος**: διαστάσεις, διάταξη διατομών, αντίγραφο σκελετού και
   ενοποίηση όλων των σταθμών σε **ένα** DXF (JavaScript).

---

## Γρήγορη εκκίνηση

Δεν χρειάζεται εγκατάσταση, ούτε build για να το χρησιμοποιήσεις:

```bash
# άνοιξε απλώς το index.html σε browser  (ή σέρβιρέ το)
python3 -m http.server 8000
# → http://localhost:8000/index.html
```

Ρίχνεις **όλα** τα DXF μαζί, πατάς Εκτέλεση, κατεβάζεις το ενοποιημένο.

### Ονοματοδοσία αρχείων (υποχρεωτική)

| Τύπος | Μορφή | Παράδειγμα |
|---|---|---|
| Ξυλότυπος | `preffix_or<N>` | `DAMAR07_or3.dxf` |
| Λεπτομέρειες υποστυλωμάτων | `preffix_Λεπτ_Υποστ_or<N>` | `DAMAR07_Λεπτ_Υποστ_or3.dxf` |

`N` από `-2` (θεμελίωση) και πάνω. Τα ονόματα σταθμών προκύπτουν αυτόματα:

| Στάθμη | Συνθήκη | Τίτλος |
|---|---|---|
| `or-2` | — | ΘΕΜΕΛΙΩΣΗ |
| `or-1` | υπάρχει `or-2` | ΟΡΟΦΗ ΥΠΟΓΕΙΟΥ |
| `or-1` | **δεν** υπάρχει `or-2` | ΘΕΜΕΛΙΩΣΗ |
| `or0` | πάντα | ΟΡΟΦΗ ΙΣΟΓΕΙΟΥ |
| `or1…orν` | ενδιάμεσες | ΟΡΟΦΗ νΟΥ ΟΡΟΦΟΥ |
| μέγιστη με ν ≥ 1 | — | ΟΡΟΦΗ ΑΝΩΤΑΤΗΣ ΣΤΑΘΜΗΣ/ΑΠΟΛ.ΚΛΙΜ. |

### Πριν την εξαγωγή από το FESPA

1. Layers **«Με χρώματα»** — όχι «Με πένες».
2. Αφαίρεση σταυρονήματος «οδηγός»/«κατασκευή».
3. Καρτέλα «Αρχιτεκτονικά ανά διαφανές»: **«Όχι»**.
4. Αφαίρεση snap «έλξεις».

## Τι κάνει το `src/merge_dxf.js`

Καθαρή JavaScript, καμία εξάρτηση. Δουλεύει σε κείμενο latin-1 (byte-προς-byte),
οπότε τίποτα δεν αλλοιώνεται. Τέσσερις δημόσιες λειτουργίες:

### `dimensionPlan(text)` — περιμετρικές διαστάσεις ξυλοτύπου

Έξω από το σχέδιο, και στις 4 πλευρές: αλυσίδα με **αρχή/τέλος κάθε περιμετρικής
κολώνας και τα κενά μεταξύ τους**, και πιο έξω μία **συνολική** διάσταση.

- *Περιμετρική* κολώνα = καμία άλλη δεν βρίσκεται πιο έξω μέσα στο ίδιο λωρίδι.
- Οι γραμμές προέκτασης είναι **προβολές από το περίγραμμα**, δεν διασχίζουν το σχέδιο.
- **Απόσταση ασφαλείας 0,25μ από ΚΑΘΕ στοιχείο** — γραμμή ή κείμενο. Τα πλαίσια των
  κειμένων υπολογίζονται με το ίδιο μοντέλο χαρακτήρων που χρησιμοποιεί το
  `pipeline/beambar_engine.py`, μαζί με ύψος, σημείο αγκύρωσης (κωδικός 71) και στροφή.
- Ύψος κειμένου 0,15 · layer `DIM_PERIMETER` (κίτρινο) · ρητή γεωμετρία, **όχι**
  οντότητες `DIMENSION` (δες «Γνωστοί περιορισμοί»).
- Στη θεμελίωση, αν δεν υπάρχουν κολώνες, χρησιμοποιούνται πέδιλα.

### `copyStructure(text)` — αντίγραφο σκελετού

Αντίγραφο **μόνο** των `COLUMN` και `BEAM` (χωρίς κείμενα/οπλισμούς) **και** των
γραμμών του layer `slab_poly`, σε **κενό 100μ** αριστερά της κάτοψης.

- Τα blocks αντιγράφονται ως νέα `INSERT` στα **ίδια** blocks — μηδενικό κόστος,
  εξ ορισμού πανομοιότυπη γεωμετρία.
- Οι γραμμές `slab_poly` ζουν *μέσα* στα `SLAB` blocks μαζί με δείκτες και κείμενα,
  οπότε αντιγράφονται μία-μία ως αυτόνομες `LINE`, με κλώνο της ίδιας της γραμμής.
- Το **κενό** είναι 100μ, όχι η μετατόπιση: υπολογίζεται από άκρο σε άκρο.

### `layoutSections(text)` — διάταξη διατομών υποστυλωμάτων

1. Ομαδοποίηση: κάθε διατομή με τα σίδερα, τους συνδετήρες, τις ετικέτες και το
   όνομά της. Σίδερα/συνδετήρες με περιεκτικότητα στο bbox, ετικέτες με το **άκρο
   της γραμμής-οδηγού**, ονόματα με τον αριθμό τους.
2. Το όνομα έρχεται όσο πιο χαμηλά γίνεται πάνω από το σύνολο, χωρίς να πατά
   `ironlabels`. Ανεβαίνει μόνο αν συγκρούεται με άλλο όνομα του ίδιου συνόλου.
3. Ομοιοθεσία σε **τελικό insert scale 2,5** (απόλυτο). Αν το INSERT δεν έχει
   καθόλου κλίμακα, γράφεται — αλλιώς οι θέσεις μεγεθύνονται και η γεωμετρία μένει 1:1.
4. Στοίχιση σε **≤ 4 σειρές** μέσα σε **ζώνη ύψους 26μ** (απαράβατο), με στόχο το
   **ελάχιστο πλάτος**. Δοκιμάζονται *όλες* οι κατατμήσεις, όχι απλή αναδίπλωση.
5. Χρώματα layer: `ironlabels_conline` → μπλε, `section_iron` → magenta.

### `mergeLevels(items)` — ενοποίηση σταθμών

Κάθε στάθμη σε δικό της «όροφο» ανά 50 μονάδες στον y:

| | pick point | προσγειώνεται στο |
|---|---|---|
| Ξυλότυπος | (max x, min y) του φέροντος σκελετού | `(0, 50·(N+2))` |
| Λεπτομέρειες | (min x, min y) των διατομών | `(5, 50·(N+2))` |

Δηλαδή ξυλότυπος αριστερά του 0, διατομές δεξιά του 5, στην ίδια σειρά.

Ο πρώτος (χαμηλότερη στάθμη) είναι «οικοδεσπότης» και δίνει HEADER/CLASSES/TABLES/OBJECTS.
Χειρίζεται πλήρως τα **handles** των R2000 αρχείων: προεργασία που χαρτογραφεί πρώτα
τις εγγραφές πινάκων (τα διπλά ονόματα δείχνουν στου οικοδεσπότη), μετά όλα τα
υπόλοιπα· το `390` (PlotStyleName) δεν λείπει ποτέ· οι ομάδες `102 {…}` που δείχνουν
σε OBJECTS που δεν μεταφέρονται αφαιρούνται καθαρά.

**Συγκρούσεις blocks**: αν δύο αρχεία έχουν block ίδιου ονόματος με διαφορετικό
περιεχόμενο, μετονομάζεται (`ΟΝΟΜΑ$L3` / `$D3`) και ενημερώνονται τα INSERT.
Χωρίς αυτό θα έχανες σιωπηλά γεωμετρία.

## Αρχές που τηρούνται παντού

- **Καμία αλλοίωση**: αλλάζουν μόνο θέσεις και κλίμακες. Το πλήθος οντοτήτων
  εισόδου = εξόδου, και ελέγχεται.
- **Κλώνοι, όχι κατασκευές**: κάθε νέα οντότητα (τίτλος, γραμμή διάστασης, layer)
  φτιάχνεται ως κλώνος υπαρκτής του ίδιου αρχείου, ώστε να έχει **ακριβώς** την ίδια
  ακολουθία group codes. Το AutoCAD απορρίπτει ολόκληρο σχέδιο για έναν κωδικό
  εκτός σειράς.
- **Κωδικοσελίδα**: τα ελληνικά γράφονται όπως τα γράφει το ίδιο το αρχείο —
  raw cp1253 όταν `$DWGCODEPAGE = ANSI_1253`, αλλιώς escapes `\U+03A9`.
- **Σειρά επεξεργασίας** ξυλοτύπου: τακτοποίηση → audit → διαστάσεις → αντίγραφο.
  Το `AUDIT_TOTAL` αφορά **μόνο** τα κείμενα οπλισμού· οι διαστάσεις μπαίνουν μετά
  ώστε να μη μολύνουν τον έλεγχο, και το αντίγραφο τελευταίο ώστε να μη μετρήσει
  στην απόσταση ασφαλείας.

## Ρυθμίσεις

Όλες στο `var CFG` στην αρχή του `src/merge_dxf.js` (και αυτούσιες μέσα στο
`index.html`, αν θες να πειράξεις χωρίς build):

| Ρύθμιση | Τιμή | Τι κάνει |
|---|---|---|
| `STEP_Y` | 50 | βήμα σταθμών στον y |
| `BASE_X` / `DETAIL_BASE_X` | 0 / 5 | x του pick point ξυλοτύπου / λεπτομερειών |
| `TITLE_H`, `TITLE_DY`, `TITLE_LAYER` | 0.60, −2.00, `LEVEL_TITLE` | τίτλοι σταθμών |
| `SEC_SCALE` | 2.5 | τελικό insert scale διατομών |
| `SEC_MAX_H` | 26 | ύψος ζώνης διατομών (απαράβατο) |
| `SEC_MAX_ROWS` | 4 | μέγιστες σειρές διατομών |
| `SEC_GX`, `SEC_GY` | 1.5, 1.5 | κενά μεταξύ διατομών |
| `SEC_LAYER_COLORS` | `{ironlabels_conline:5, section_iron:6}` | επιβολή χρωμάτων |
| `DIM_TEXT_H` | 0.15 | ύψος κειμένου διαστάσεων |
| `DIM_SAFE` | 0.25 | απόσταση ασφαλείας από κάθε στοιχείο |
| `DIM_LAYER`, `DIM_COLOR` | `DIM_PERIMETER`, 2 | layer/χρώμα διαστάσεων |
| `DUP_GAP` | 100 | κενό αντιγράφου σκελετού |
| `DUP_RE`, `DUP_LINE_LAYERS` | COLUMN\|BEAM, `['slab_poly']` | τι αντιγράφεται |

## Γνωστοί περιορισμοί

- Οι διαστάσεις είναι **ρητή γεωμετρία** (γραμμές + ακίδες + MTEXT), όχι οντότητες
  `DIMENSION`. Άρα δεν είναι συσχετισμένες ούτε επεξεργάσιμες ως διαστάσεις. Μια
  πραγματική `DIMENSION` απαιτεί `DIMSTYLE` + ανώνυμο block ανά διάσταση + block
  ακίδας — δηλαδή έτσι κι αλλιώς σχεδίαση της γεωμετρίας, συν τρία επίπεδα δομής
  που το AutoCAD ελέγχει αυστηρά.
- Οι διαστάσεις μπαίνουν όσο πιο κοντά επιτρέπει το περιεχόμενο **της κάθε στάθμης**,
  οπότε δεν είναι στην ίδια απόσταση σε όλες.
- Το `tests/run_project.js` δεν τρέχει την τακτοποίηση οπλισμού (Python/Pyodide).
  Ελέγχει το JS κομμάτι. Η πλήρης ροή τρέχει στη σελίδα.
- Κενά blocks που παράγει καμιά φορά το FESPA (π.χ. `FOOTING` χωρίς γεωμετρία,
  `SECTION` χωρίς περίγραμμα) παραλείπονται με ρητό μήνυμα στο log.
